# ADR-0003：日志事件流、缓存和文件保留边界

- 状态：已接受
- 日期：2026-09-01
- 关联计划：[TunnelPad 日志事件流与面板生命周期](../plans/tunnelpad-log-streaming.md)

## 背景

当前 `LogView` 在窗口可见期间每 2 秒读取日志文件末 500 行。当前运行路径由 `launchd` 把 stdout/stderr 写入每隧道日志文件，Rust Core 负责隧道生命周期 owner。阶段 0 的隔离基线确认现状没有统一追加事件、后台采集缓存或本地文件 2000 行裁剪。

## 决策

1. 当前范围只接入 `launchd` 文件日志；Rust Core 继续是隧道生命周期唯一 owner，未来 `app` 执行器输出另立计划，不在本 ADR 扩大输入范围。
2. 在 Swift `TunnelPadCore` 内增加进程内日志存储与事件适配层。每条隧道独立维护缓存、文件读取 offset、文件身份、事件版本和订阅者。
3. 每条隧道内存缓存最多保留 500 条，单行最多 8000 字符；不增加配置项，超限淘汰最旧条目。缓存淘汰不回写文件，事件版本即使缓存条数不变仍保持单调递增。
4. 持久日志的保留目标与压缩触发边界由[日志低写放大计划的不变量](../plans/tunnelpad-log-write-amplification.md#不变量)承载；该已完成后续计划细化了原来的逐次行数保留策略。裁剪仍采用原位、可恢复的写入边界，尽量保持文件路径和 inode 不变；检测到并发变化、无法安全锁定或写入失败时延后裁剪并保留原文件，不删除、替换或伪造日志。
5. `LogSnapshot` 表示某隧道当前完整可显示快照，包含隧道 ID、单调 `UInt64` 版本、文本和文件状态；`LogEvent` 包含相同隧道 ID/版本、追加文本和对应快照；`LogSession` 通过“先读取快照、再在同一 actor 串行域注册订阅”的衔接返回当前快照与事件流。消费者只应用隧道 ID 匹配且版本更大的快照。
6. 面板只在可见期间订阅当前隧道；关闭或隐藏只取消 UI 订阅，不停止后台采集、文件写入或缓存。重新打开先建立会话再渲染快照；切换隧道取消旧会话并使用新隧道 ID/代次隔离迟到事件。
7. 无新文件字节时不产生日志事件，UI 不再用固定周期 Timer 作为变化检测。后台文件监听允许事件合并，但每次读取以文件身份和 offset 校正截断/替换。

## 后果

- 日志写入和 UI 生命周期解耦，面板关闭期间仍能累积近期日志，重开可从缓存或文件恢复。
- 事件、缓存、订阅和版本属于进程内状态，不改变 `config.json`、HTTP API、plist 日志路径、stdout/stderr 路由或 Rust ABI。
- 文件裁剪与 `launchd` 并发写入存在竞态，必须通过隔离 fixture 覆盖追加、截断、替换、锁失败和异常中断；正常追加期间与安全失败时的暂时超限均按上述唯一来源处理。
- `TunnelManager`、主面板和日志视图是共享高影响区域，实现需按计划治理串行编辑，并在提交前运行 GitNexus `detect_changes()`。

2026-09-06 文档同步说明：本次仅将保留策略指向已经完成并通过独立复核的后续专项计划，不新增运行行为或改写本 ADR 的历史日期。

## 回滚

若事件订阅、裁剪或 UI 生命周期验证失败，可按阶段独立回滚新增事件适配层和 UI 订阅，恢复文件快照显示；不删除日志文件、不覆盖真实 plist、不修改 Rust Core owner。回滚期间仍可读取现有日志文件末 500 行作为兼容显示路径。
