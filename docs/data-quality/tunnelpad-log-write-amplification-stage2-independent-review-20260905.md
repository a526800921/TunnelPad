## 已有现场证据

- 两个现有隧道均已在最新 Release App 中启动，API 健康检查为 `ok`。
- 两个隧道的独立 `-v` 均已关闭；关闭后 40 秒窗口内日志大小、mtime 和 `debug1` 计数未变化，SSH CPU 采样为 `0.0`。
- 详细日志开关已做一次真实回归：开启后诊断计数增加，关闭并重启后配置恢复静默；该回归不改变密钥、连接参数或远端资源。

## 阶段 2 尚未完成的验证

1. 两个隧道静默运行至少 30 分钟，按分钟记录日志大小、mtime、行数、`debug1` 计数、SSH CPU 和本地 API 状态。
2. 在窗口开始和结束读取 Activity Monitor 的 TunnelPad CPU/能耗/磁盘累计指标，并与阶段 0 的约 57 KiB/s 写放大投影比较。
