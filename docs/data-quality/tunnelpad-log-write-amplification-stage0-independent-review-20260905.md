## 证据

### 真实 Release App 基线

在用户授权的真实本机环境中进行只读观察，输出保存在 `/tmp/tunnelpad-log-write-amplification-stage0-20260905.txt`：

- `admin-tunnel.log`：199,557 字节、2000 个 LF 逻辑行。
- `reverse-ssh.log`：129,025 字节、2000 个 LF 逻辑行。
- 两个日志在观测窗口内大小没有增长。
- `admin-tunnel.log` 修改时间在约 10 秒间隔更新，文件大小保持 199,557 字节；`reverse-ssh.log` 没有同频更新。
- 当前两个隧道配置都包含独立 `-v`；该事实只记录参数开关，不记录密钥、地址或完整命令。
- 前一轮 Activity Monitor 进程累计写入差值约 1.7 MB/30 秒，折算约 57 KB/s；该数值是累计进程写入，不等同于日志新增量。

该证据确认：日志新增量很小，但当前保留路径会重复写入约 200 KB 的已有内容；问题属于应用日志级别和裁剪触发策略叠加造成的写放大，不是远端隧道流量本身。

### 实现与契约基线

- `launchd` 直接持有固定日志路径的 stdout/stderr 文件描述符；重命名替换会有写入旧 inode 的风险。
- `LogEventStore.refreshState` 在文件变化时执行日志状态刷新；现有 `LogFileRetention` 只有在超过 2000 行后才能安全压缩。
- 普通文件可以流式追加，但删除文件头仍需要搬移后续字节或使用独立日志代理；本阶段不引入 helper、FIFO 或环形文件。
- 既有 500 条内存缓存、8000 字符单行上限、LF/CRLF 行语义、固定路径、锁失败保留原文件和 Rust Core lifecycle owner 均作为不变量保留。
