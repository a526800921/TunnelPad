# ECS 动态 SSH 公网 IP 同步：阶段 0 项目外受控实跑

日期：2026-08-29
性质：项目外本机直调 ECS API 的受控实跑记录；不包含 AccessKey、Secret、原始公网 IP、完整资源标识或完整规则 ID。

## 前置条件

- 新专用 RAM 身份已通过 STS 与目标安全组只读验证；现有 FullAccess 凭证未参与。
- 用户确认本机直调，不增加中央执行器；并报告已保存 `AuthorizeSecurityGroup` 与 `RevokeSecurityGroup` 的策略修正。
- Workbench 已由用户确认可用，作为独立恢复通道。
- 两个禁用代理、强制 IPv4 的 HTTPS 端点返回一致的合法公网 IPv4；本次地址哈希为 `b6ad59297aa31858`。用户随后报告本机运行代理，因此该结果不能单独证明 SSH 实际来源。
- 写入前读取确认不存在描述为 `tunnelpad-dynamic-ssh-managed` 的既有受管规则。

## 目标确认与实际 SSH 路径

- 用户本轮明确指定并通过 Workbench 成功连接本计划的目标 ECS；Workbench 会话地域为 `cn-chengdu`，实例标识不在本证据中记录。
- 复查仓库现有生产 SSH 配置 `../motorcycle-manual-app/infra/production/ssh_config` 后，使用该配置的 `motorcycle-manual-prod` 已直连同一目标公网入口，非交互式 SSH 测试成功。
- 先前“SSH 别名与受控 ECS 不一致”的判断来自未加载生产 SSH 配置的默认 `ssh -G` 检查；本次复测已纠正该诊断，不再作为阻塞项。
- 从真实 SSH 会话的 `SSH_CONNECTION` 读取来源，仅保留哈希 `60056a68ff9e948d`；该哈希与代理环境下两个 HTTPS 探测结果 `b6ad59297aa31858` 不一致，因此后续同步使用实际 SSH 会话来源，不使用普通公网 IP 探测值。
- 进一步按当前 Clash/TUN 路由验证两个中国直连 IPv4 回显端点：`myip.ipip.net` 与 `ip.3322.net` 均返回与 SSH 来源相同的哈希 `60056a68ff9e948d`，且两端点彼此一致。它们可在 SSH 断开时作为预连接探测；探测结果不一致或与已验证 SSH 来源不一致时必须停止写入。
- 复核安全组时观察到 `createdByEcsWorkbench` 和 `System created rule.` 类型的 SSH 规则，以及原有无描述规则；这些均不是本计划的管理对象，动态流程只精确匹配 `tunnelpad-dynamic-ssh-managed`，不按端口批量清理。

## 当前结论

- 新专用 RAM 身份的本机 `AuthorizeSecurityGroup` 实际授权已验证可用。
- 目标 ECS 已通过 Workbench 与生产 SSH 配置双路径确认；实际 SSH 会话来源已观察到并用于一次“新增、确认、清理旧受管规则”的受控同步。
- 代理环境下两个 HTTPS 探测值与真实 SSH 来源不一致，证明普通公网 IP 探测不能作为本流程的来源基线；应以实际 SSH 路径可观察到的来源为准，或在后续命令中复用同一路由。
- 受控同步和规则收敛已完成，规则收敛后 SSH 重连成功；但“SSH 已经完全断开时，如何在新增规则前取得同一来源”尚未验证，因此本次运行不能单独证明断连恢复场景已闭环。
- 两个直连 IPv4 回显端点已与 SSH 来源完成双源一致性验证，补齐了断连前的来源发现路径；运行时仍须保留双端点一致性和历史来源校验，任何不一致都不写云端。
- 本证据仍需阶段 0 的独立准入复核；复核前不能冻结阶段 1 的仓库命令契约。
- 任一后续失败均不得删除当前受管规则；Workbench 继续作为恢复通道。
