# ECS 动态 SSH 公网 IP 同步：阶段 0 云端只读验证

日期：2026-08-29
性质：身份与安全组只读验证的追加记录；不是安全组写入或受控实跑证据。

## 范围与安全边界

- 使用新专用 RAM 用户结果 CSV 的数据行，仅在本机进程中创建仓库外隔离阿里云 CLI profile；配置文件仅当前用户可读，路径及任何凭证值不写入仓库。
- 未读取、复制或导入现有 `AliyunECSFullAccess` 凭证 CSV。
- 首次本机 `sts GetCallerIdentity` 命令在参数解析阶段失败：当前 CLI 不接受 `--output json` 形式，且 profile 已设置 JSON 输出。移除该参数后，STS 确认该 profile 是 RAM 用户；不输出或记录原始响应、账户、主体、资源、AccessKey、Secret、密码、邮箱、手机号或公网 IP。
- 随后目标安全组的只读查询曾被 `Forbidden.RAM` 拒绝。用户修正精确只读策略后重试成功：该组有 5 条入方向规则，其中 2 条为 TCP SSH，未发现来源为 `0.0.0.0/0` 的 SSH 放行。该结果只覆盖本安全组，不能推断实例未关联的其他安全组；未调用任何安全组写接口，也未修改任何云端资源或规则。

## 样本结果

| 样本 | 动作 | 结果 | 结论 |
|---|---|---|---|
| 隔离 CLI profile | 用官方 CLI 兼容的 AK 配置结构在仓库外创建命名 profile，文件权限收紧为仅当前用户可读 | 已建立 | 凭证未进入仓库；后续调用固定使用该隔离 profile。 |
| 专用身份归属 | 移除不兼容输出参数后调用 `sts GetCallerIdentity`，仅在本机检查身份类型类别 | 确认为 RAM 用户 | 新专用身份可进入安全组只读权限验证。 |
| 安全组规则读取 | 用户修正精确只读策略后，调用目标安全组的 `DescribeSecurityGroupAttribute`，仅请求入方向规则 | 成功读取 5 条入方向规则；2 条 TCP SSH；未发现宽泛 SSH 放行 | 结果只覆盖本安全组；未确认关联的其他安全组前不进入实跑。 |
| 安全组写入 | 未执行 | 无 `AuthorizeSecurityGroup`、`RevokeSecurityGroup` 或等效接口调用 | 安全边界保持。 |

## 下一步

1. 通过控制台或最小只读 API 确认目标网卡关联的全部安全组，并逐组执行相同的 SSH 宽泛规则检查。
2. 在不调用云端接口的前提下，运行两个公网 IPv4 端点的本机探测并比较结果；只记录一致性结论与地址哈希。
3. 确认 Workbench 恢复通道后，才设计安全组写权限边界；若身份不符、读取权限不清或规则基线不完整，停止阶段 0，不调用任何安全组写接口。
