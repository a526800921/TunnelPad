## 发现

1. 共享 `checkLaunch` 会按 ECS resource 合并结果，若把清理并入其中，第二条隧道会跳过自己的端口清理。
2. “专用端口＋唯一 PID＋同 UID＋`sshd`”不能区分另一台主机或重复配置的健康会话，监听归属不足。
3. 仅重读相同 PID 不能消除 PID 复用，至少需要 start time、socket inode 等稳定身份，优先使用 pidfd。
4. 在远端 helper 内等待并升级 KILL，会在本地取消/超时后留下仍可继续发信号的远端动作。
5. SSH 允许列表和 shell 边界不完整，尚未排除配置文件、代理命令、控制套接字、remote command、合并参数等执行入口。

## 用户追加决策

用户随后要求新增默认关闭的逐隧道强杀配置，并明确 `motorcycle` 的 `18080` 是排他端口：配置开启后，不检查 IP、UID、`sshd` 或会话归属，任何监听该远端 TCP 端口的进程都必须被强制结束。该显式权限取代第 2 项原“证明旧会话归属”的前提，但只允许应用于明确开启的隧道；其他四项仍须按复核要求修复。

## 要求的验证增量

- 同 ECS 不同端口共享同步但逐隧道清理；相同远端键只串行、不共享结果。
- 新字段缺省关闭，UI 风险说明和配置持久化一致；关闭时不建立清理 SSH。
- IPv4/IPv6、任意绑定地址、多 socket、多 PID 监听目标端口时全部强杀并确认释放。
- PID 复用时必须由 pidfd 和监听复核阻止错误信号，不得降级普通 `kill PID`。
- 取消覆盖信号前、信号后和最终确认前，远端无延迟动作。
- helper 缺失/不可执行/版本不匹配/Release 遗漏全部 fail-closed。
- `-F/-J/-S/-W/-D`、危险 `-o`、多个目标、remote command、合并参数等负向测试均不得进入信号路径。
