# 计划：ECS 动态 SSH 公网 IP 同步

## 背景

本机网络切换会改变公网 IPv4，使仅允许旧来源 `/32` 的 ECS SSH 安全组规则失效。本计划以仓库内的独立辅助命令同步 SSH 来源地址，可与 TunnelPad v1 并行进行阶段 0 准备；当前不把阿里云凭证、ECS 配置或同步逻辑纳入 TunnelPad v1 的 UI、`config.json` 或启动链路。

[ecs-dynamic-ssh-ip-design.md](../ecs-dynamic-ssh-ip-design.md) 是初始背景材料。本计划是本事项的唯一规范事实源。

## 目标

在不扩大公网入口、不读取 SSH 私钥内容、不把云凭证写入仓库的前提下，提供一个可审计、可回滚的本机命令：确认本机实际 SSH 出站公网 IPv4 后，只维护目标 ECS 动态 SSH 安全组的一条 TCP SSH `/32` 入方向规则。

## 非目标

- 阶段 1 不修改 TunnelPad UI、`config.json` schema、启动流程或 launchd 执行器。
- 不使用、不读取、不迁移现有的 `AliyunECSFullAccess` 凭证 CSV。
- 不创建 `0.0.0.0/0`、IPv6、私网或端口范围宽于 SSH 端口的规则。
- 不自动删除未知来源的安全组规则，也不管理 80/443、ECS 服务、Caddy、systemd、SSL-VPN 或 Workbench。
- 不将 AccessKey、Secret、SSH 私钥、完整安全组/实例 ID 或原始公网 IP 写入仓库、日志或证据文档。

## 需求探索

### 已确认事实

- 用户确认本事项是独立优化计划，可立即开始阶段 0 准备，但不改变 TunnelPad v1 的范围。
- 第一实施阶段只交付仓库内独立同步命令与安全预检；TunnelPad 自动启动前调用是后续候选阶段。
- 现有下载目录中的 AccessKey 具有 `AliyunECSFullAccess`，明确排除在本计划外。
- 以后如实施云 API 调用，用户会新建专用 RAM 凭证；在最小权限边界可接受前不得启用。

### 暂定假设与验证方式

| 假设 | 验证方式 |
|---|---|
| SSH 到目标 ECS 是本机直连，公网 IP 服务得到的地址就是 ECS 观察到的源地址 | 阶段 0 固定目标 SSH 别名，运行 `ssh -G`；`ProxyJump`、`ProxyCommand` 或不确定的 VPN/代理出口均视为不通过。 |
| 专用动态 SSH 安全组已关联到承载 SSH 公网流量的 ECS 网卡 | 阶段 0 通过控制台或只读 ECS 查询记录脱敏关联关系，并检查所有相关安全组。 |
| 不存在会绕过动态规则的宽泛 SSH allow 规则 | 阶段 0 查询目标网卡相关安全组；发现 `TCP 22/22 + 0.0.0.0/0` 或等效覆盖范围即不通过。 |
| 新 RAM 身份的实际授权范围足够窄 | 阶段 0 先做策略与只读身份验证；若不能证实其风险边界可接受，停止计划，不进入阶段 1。 |

### 范围与非目标

范围：阶段 0 形成只读基线和权限可行性结论；阶段 1 在仓库内交付独立命令、测试和操作说明。TunnelPad 自动调用、凭证保管 UX 与配置 schema 扩展不属于阶段 1。

非目标：见本计划“非目标”章节。

### 候选方案与取舍

| 决策点 | 候选 | 当前结论 |
|---|---|---|
| 规则归属 | 专用动态 SSH 安全组 / 在现有组以描述标记维护 | 优先专用安全组；仅在已关联且没有宽泛 SSH 规则时使用。无法新建时，允许在现有组中以精确描述和完整规则元组识别。 |
| 触发方式 | 手工执行 / SSH 前置 wrapper / TunnelPad 自动调用 / 定时任务 | 阶段 1 只交付手工命令与可选 SSH 前置 wrapper；自动调用和定时任务留到后续阶段。 |
| 凭证 | 现有 FullAccess / 新专用 RAM 身份 / RAM 角色或临时凭证 | 排除现有 FullAccess；阶段 0 验证专用身份的最小权限可行性，优先避免长期高权限密钥。 |

### 未决问题

| 问题 | 影响 | 阻塞级别 |
|---|---|---|
| `ecs:AuthorizeSecurityGroup` 能否在实际 RAM 策略中限制到可接受的安全组与规则范围 | 决定专用凭证是否可安全启用 | 阻塞阶段 1 |
| 目标 SSH 的实际出站路径是否为直连 IPv4 | 决定公网 IP 探测是否有效 | 阻塞阶段 1 |
| 专用安全组的关联与现有 SSH 规则是否满足收紧条件 | 决定同步命令是否会生效且不会留下宽泛入口 | 阻塞阶段 1 |

### 用户确认的探索结论

2026-08-29 用户确认：本事项新开为 TunnelPad 后续优化计划；阶段 1 只做仓库内独立同步命令与安全预检；TunnelPad 自动集成推迟到后续阶段；现有 `AliyunECSFullAccess` 凭证永不用于该能力，另建专用凭证且仅在最小权限边界验证通过后启用。

## 不变量

- 更新顺序必须是“新增当前规则 → 查询确认 → 按规则 ID 清理已验证的旧规则”；新增失败时保留旧规则，删除失败时保留新旧规则并报告失败。
- 只操作方向 `ingress`、`TCP`、`<SSH_PORT>/<SSH_PORT>`、`accept`、VPC `intranet`、描述精确匹配的动态 SSH 规则；绝不按“所有 22 端口规则”批量删除。
- 每次 API 写操作必须带唯一 `ClientToken`；重试或规则 ID 不存在时必须重新查询收敛状态，不能把未知错误视为成功。
- 单次运行最多接受一个经过严格校验的公网 IPv4，并写为 `/32`；任何空值、私网/保留地址、IPv6、两个来源不一致或异常响应都会终止且不写云端。
- 使用本地互斥锁；日志仅保存脱敏资源标识、规则 ID、结果和时间，绝不包含凭证或原始公网 IP。
- Workbench 保留为恢复通道；脚本、TunnelPad 和动态安全组都不得成为唯一 SSH 恢复方式。

## 当前阶段

当前阶段为阶段 0（只读基线与权限可行性）。

阶段 0 可立即实施，且只包含本计划的只读基线与权限可行性工作；不得改动 TunnelPad v1 代码或自动集成链路。

### 范围

- 固定目标 SSH 别名及其真实出站路径；不处理经跳板、代理或不确定 VPN 出口的情况。
- 获取目标 ECS 网卡关联安全组、SSH 入方向规则和专用动态组关联关系的脱敏只读快照。
- 排除宽泛 SSH 规则，验证专用安全组方案能实际约束入口。
- 设计并验证新的专用 RAM 身份的权限边界；只读身份验证不得使用或读取现有 FullAccess CSV。

### 非目标

- 不调用 `AuthorizeSecurityGroup`、`RevokeSecurityGroup` 或其他写接口。
- 不创建 RAM 用户、AccessKey、安全组、ECS 配置或 TunnelPad 代码。
- 不把原始网络、账户或凭证数据写入仓库。

### 实施步骤

1. 用户在实施前自行提供一个新的专用 RAM 身份；不得提供或导入现有 FullAccess CSV。
2. 以只读命令记录 SSH 配置、目标安全组关联及入方向 SSH 规则的脱敏基线。
3. 检查是否存在绕过动态组的宽泛 SSH 允许规则；若存在，记录为阻塞项，不执行任何删除。
4. 用新身份仅验证身份归属与预期只读权限；记录策略边界结论，不调用写接口。
5. 填写阶段 0 证据、独立准入复核，并同步 `PLAN_MAP.md`；复核通过后才冻结阶段 1 命令契约。

## 风险和回滚

- 凭证或策略过宽：阶段 0 即阻止推进；不使用现有 FullAccess CSV。若未来专用凭证泄露，立即在 RAM 禁用/删除该专用凭证，且不影响现有 SSH 私钥。
- 安全组误配：阶段 1 的顺序固定为先新增、确认后清理；失败保留旧规则。Workbench 是恢复通道。
- 出站 IP 误判：端点不一致、代理、VPN 或跳板均不写入安全组；改由人工路径分析或保持手动访问。
- 并发执行：本地锁失败或持锁不明时不写入；由操作者检查后重试。
