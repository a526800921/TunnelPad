# 计划：TunnelPad 无人值守启动恢复

## 背景

2026-09-12 用户明确需要无人值守，并要求为启动失败后的自动恢复建立新计划。已完成的[开机自启与隧道自动恢复](tunnelpad-launch-autostart.md)只尝试一次：登录时网络尚未就绪或 ECS 前置检查失败，网络恢复后仍需手动启动。既有[无人值守受管 SSH 收敛恢复](tunnelpad-unattended-managed-ssh-recovery.md)负责运行后的故障恢复，不能替代首次启动失败的重试。

本计划承接旧计划“不为启动恢复增加自动重试循环”的后续演进；阶段 1 工作树与隔离包已实现持续恢复，真实运行实例及验收仍待阶段 2。原计划完成证据保持历史含义。

## 目标

- 用户登录 macOS、TunnelPad 启动后，标记 `autoStart=true` 的隧道即使首次启动失败，也能在临时故障消失后自动运行，无需点击启动或重启 App。
- 在网络长期不可用时维持有上限的重试频率；多隧道隔离、界面响应、退出清理和现有健康恢复保持有效。
- 启动请求完成、已运行、健康检查通过分别记录，不用请求完成冒充恢复成功。

## 非目标

- 不提供用户登录前的系统守护服务，不自动登录 macOS，不绕过 FileVault、登录项审批或凭据权限。
- 不新增 app 执行器；保留 Rust owner、现有 SSH 进程收敛及健康恢复机制，补充自动启动所需的严格入口和前置监督边界。
- 不修改本机 HTTP API 或远端资源授权范围，不为重试自动扩大 ECS 权限。
- 用户已明确授权阶段 1 自动重试、前置加固、隔离测试与打包检查；阶段 2 真实环境操作及发布仍需具体授权。

## 需求探索

已确认：无人值守是本次新需求，不再接受临时网络失败后必须手动启动的兜底。用户明确暂不处理旧单次恢复队列的极端竞态；此次已授权的日志修复单独记录于[后续复核与日志修复](../reviews/tunnelpad-launch-autostart-followup-20260912.md)，不作为新重试机制的实施授权。登录项错误提示问题目前只解释、未修复。

阶段 0 已从代码与隔离样本确认：不能只给 `startAsync` 外包重试。详细事实见[阶段 0 基线](../data-quality/tunnelpad-unattended-launch-recovery-stage0-step0-20260912.md)，冻结契约如下；阶段 1 已实现，隔离验证及独立恢复通过，真实场景由阶段 2 验收。

### 调度、状态与交接契约

1. **候选**：本次启动读取首份有效配置，冻结 `(id, 配置代次)` 候选集合；初始配置不可用时限频重读，但不在首次成功冻结后扩大集合。空候选直接完成。后续新增/首次勾选只在下次 App 启动参与。
2. **单调退避**：第一次立即尝试；第 1–4 次失败后分别等 5、15、30、60 秒，第 5 次及以后 300 秒。以每次操作及清理结束为起点，使用单调时钟，当前版本不加随机抖动。进程重启重新计时；睡眠唤醒后只执行一次到期检查，不补发错过的多轮。临时错误不因总次数永久熔断。
3. **调度容量**：全局最多 2 条启动尝试；每 ID 最多 1 条；同一 ECS 资源最多 1 次前置同步，锁/journal 资源键为 region/security-group 的规范组合（日志仅哈希），profile 只选择凭据、不能把同一远端资源分成两把锁。若实际资源身份无法解析，使用更粗的全局互斥并保持 fail-closed。等待资源令牌不占全局执行槽，按到期时间与入队序公平推进；App 的启动、手动及健康恢复共享前置资源互斥，外部脚本由同一内核锁约束。
4. **状态机**：`waiting → checking → preflight → starting → observing → handedOff`；失败转 `waiting` 或 `pausedPrerequisite`；取消转终态 `cancelled`。所有跨 await 提交都校验 ID、配置代次、操作代次及退出标记。不能依据 `statuses` 是否非空、旧缓存、探针通过或网络通知推定已取得可信状态。
5. **严格入口**：启动队列使用单条 checked 状态读取和新的 Rust 原子自动启动入口；在同一条隧道锁内再次校验代次、deadline、当前配置和 checked 状态，只有确证 `notLoaded` 才写 plist/bootstrap。已运行直接交接；`notRunning/other` 不重复 bootstrap。Rust 现有手动 start 的 fallback 不作为自动启动依据，旧 API 行为不在本计划顺便改动。
6. **已加载作业**：`notRunning` 且 KeepAlive=true 时保留 `observing`，按退避查单条状态，让 launchd 重连；不因观测超时反复卸载。KeepAlive=false 的已加载停止作业，先走既有受管 stop 收敛，确证未加载后重新前置并严格启动。`other` 始终只观察/限频重读。运行态须有有效 PID 的 fresh checked 证据后才交接；探针健康是独立验收，不把健康要求新增给无探针隧道。
7. **恢复所有权**：处于启动队列的 ID 不推进健康恢复失败计数、不创建健康恢复任务；第一次确认运行后在 MainActor 内原子注销启动 owner、重置健康计数并交接。运行后的失败只由原健康机制和 KeepAlive 处理，不重新加入启动队列。
8. **取消优先**：手动 stop/restart/start、关闭 autoStart、删除及命令/执行器/KeepAlive/探针等运行配置变化，先失效并取消启动任务，再执行用户命令；备注/显示名称变化不重新排队。旧任务清理完成前不释放其副作用槽，同 ID 重建不继承资格。退出先设置全局 stopping、取消/收敛前置任务，再执行 Rust shutdown。该边界服务于新增长期队列，不追补用户暂不处理的旧单次队列竞态。

### 错误与前置检查契约

不能从 `lastError` 文案或单一 exitCode 推断重试类别。保持手动 UI/API 结果兼容，新增内部结构化启动结果及脚本可选的机器结果模式（`resultVersion=1`，仅 stage、category、retryHint、sanitizedCode）；默认 CLI 文案/退出码兼容。原始 stdout/stderr、云响应、凭据和完整命令不得进入结果或 App 日志。

| 分类 | 可靠来源 | 行为 |
|---|---|---|
| transient | 明确网络/限流/服务暂时不可用、受控超时 | 按启动退避持续重试，每次前置重新成功才可启动 |
| localPrerequisite | 缺失工具/脚本、配置格式错误、不可读凭据 | 暂停外部写操作，300 秒本地重新验证；恢复后立即排队，不靠文件 mtime 单独判断 |
| authentication | 脱敏结构化云错误明确认证或权限拒绝 | 暂停写操作；同资源每 1800 秒最多一次远程只读重验证，凭据变更可唤醒但仍受此频率上限；服务端权限恢复也能自动发现 |
| resourceBusy | 活跃资源锁或已有在途副作用 | 等待资源/退避，不能当作启动失败继续叠加同步进程 |
| transactionPending | 本计划 supervisor 的可信未完成事务 | 同资源锁内重新查询并按下节续作；期间禁止隧道启动 |
| unsafeAmbiguity | 无可信记录的多规则、记录不一致、外部状态冲突 | 禁止云写和隧道启动，低频只读观察并提示需要处理；不能为无人值守删除未知资源 |
| unknown | 老脚本/无法可靠识别的新云错误 | 300 秒只读重验证，确证前置可用才进入正常同步；绝不把未知视为成功/未加载 |
| cancelled / stale / ownerClosed | 类型化取消、代次与退出结果 | 终止本次任务，不重试、不污染用户错误提示 |

旧退出码 4 同时代表读取失败和规则歧义，5/6 也可能存在未确认的已生效写操作；兼容适配器只能把它们归 unknown/需重查，不能永久分类为认证错误或直接重复写。远程只读重新验证同样需要认证和网络，不宣称为纯本地检查。

### 超时、互斥与事务边界

- **预算**：单条完整尝试从获得执行槽起最多 60 秒，工作截止在第 55 秒，保留最多 5 秒清理。checked 状态查询单次最多 2 秒；ECS 前置整体最多 30 秒（双 IP 探测及所有云调用共用剩余预算）；bootstrap 子过程最多 10 秒；启动后 fresh 状态收敛总窗口最多 10 秒。所有子预算取剩余总预算的最小值，不能把每次状态查询的 2 秒额外累加到窗口外。Rust 等锁也必须可取消、有剩余预算，不能仅包一个 Swift 超时任务后遗弃 detached 调用。
- **前置监督**：阶段 1 增加随包分发的原生 preflight supervisor（Rust，同一发布版本，非常驻 daemon），由所有 App/CLI 前置调用共同使用。它持有资源互斥、总预算与专用进程组身份，启动脚本和子孙进程；取消先请求正常退出，到宽限则只终止可证明属于该次监督的进程组，等待回收并关闭管道。脚本 INT/TERM 必须终止控制流，不能仅清锁后继续云写。监督结束确认前不得释放同资源资格；无法确认时隔离该资源，不启动下一次副作用。
- **锁**：新路径使用受保护目录内的内核 advisory lock，锁随监督及受监督子进程存活，避免崩溃留下永久目录锁。兼容窗口采用共同原子互斥：新 supervisor 在持新锁后还须用与旧路径相同的 `mkdir` 原子持有旧目录锁，并写入可信 owner 标记，持续到所有子进程及本地写请求结束；锁获取失败则释放本次新锁并退避。不能只“检查旧目录不存在”再继续，不能因已有新锁而跳过旧锁。仅回收带本版本可信 owner 身份且已确认所有持有者死亡的遗留标记；未知旧锁保持 fail-closed 并说明迁移前提，不按 mtime/PID 单独判定死亡。旧脚本只获取旧锁，无反向获取顺序；打包、独立脚本调用、旧新版本竞争及锁文件权限作为阶段 1 必测项。
- **远端请求不确定性**：杀掉本地客户端不代表已提交的云请求被撤回。supervisor 在发起写操作前持久化本地受保护事务记录（仅资源身份、精确规则 ID/形状摘要、阶段和幂等 token，不含密钥）；重试先读取云端结果，沿用同一 token 或确认最终状态，不能盲目创建新写请求。
- **精确续作**：若前一次确认新规则后撤销旧规则失败，只能续作记录中那一条旧规则 ID，并重新验证资源、记录完整性和新旧规则全部限定属性。未知多规则、第三条意外规则、属性变化或记录损坏均禁止自动撤销。若旧规则已不存在且新规则唯一，直接完成；若授权结果未确认，先以相同 token 和严格查询确认新规则身份，禁止在新规则确认前撤销旧规则。IP 在事务间变化时先完成原可信事务，再针对当前 IP 发起下一次正常同步，不能叠加第三条规则；隧道启动须等当前来源最终同步成功。
- **持久化失败**：无法安全记录事务即禁止云写；事务以原子替换和落盘顺序覆盖发请求前、确认后、撤销前与完成后崩溃点。状态文件不作为可执行命令来源；权限/符号链接/所有者异常均 fail-closed。该运行时记录新增迁移与回滚责任，阶段 1 完成前补正式 migration 文档。
- **能耗及日志**：只管理待恢复集合和到期任务，不增加全量周期 snapshot；成功/无候选后没有启动重试唤醒。相同原因去重，只记录首次、类别或退避阶段变化、最终运行/暂停/取消；长期相同错误最多每资源每 30 分钟一条摘要，沿用日志限量。U9 以真实采样验收，虚拟时间计数不冒充 CPU/能耗结果。

以上续作只演进本计划可信操作导致的未完成同步，不授权清理任意 ECS 规则；历史人工处理约定对无法证明归属的情况仍然有效。

## 不变量

- Rust Core 仍是配置、生命周期与进程信号唯一 owner；Swift 只负责既有边界内的调度编排。
- ECS 前置检查每次启动仍须通过；网络恢复信号不能替代前置成功或授权。
- 状态未知时禁止启动；已运行的受管实例不重复启动，不终止未知进程。
- 退出 App 停止隧道并取消启动重试；关闭窗口仍常驻。
- 默认 `autoStart=false`、schema version=1 和新增隧道不立即自启保持兼容。
- 高影响生命周期变更按风险分流完成适用独立复核；不能用文档结构通过代替实现或业务验收。

## 公共契约变化

本计划的“需求探索”承载目标行为、内部状态/错误及时间契约。现行配置仍由 [TunnelConfig.swift](../../Sources/TunnelPadCore/TunnelConfig.swift) 和 [Rust 配置定义](../../rust/tunnelpad-core/src/lib.rs) 承载，schema version=1、HTTP API 不变。

阶段 0 已确认必须追加内部 JSON 命令契约：严格自动启动请求携带 id、必需 generation、剩余 deadline，结果区分 running/loadedWaiting/unknown/cancelled/failed；Rust 在锁内校验 fresh checked 状态，只能从 notLoaded 执行 bootstrap。C 函数签名不变，新增命令需同版 Rust 动态库与 Swift 客户端配套发布；旧库不识别时禁用自动队列并明确报错，不回退到宽松 start。具体字段 Schema、错误码和 capability fixture 在阶段 1 Step 0 固定并做差分验证。

脚本追加可选机器结果模式与 supervisor/事务记录，不改变默认退出码含义；部署兼容、旧锁共存及有未完成事务时的回滚由阶段 1 migration 承载，不能只回退 App 二进制后遗留事务无人管理。

## 风险和回滚

- 主要风险：副作用超时后旧任务迟到、自动恢复互相竞争、用户取消后复活、持续故障放大云请求/日志/能耗；在阶段 0 冻结可执行失败边界。
- 任何前置或身份不明确均 fail-closed，保持限频等待，禁止绕过权限追求恢复。
- 未来功能回滚时先取消队列并确认副作用收敛，再处理可信未完成事务；禁止直接删除 journal 或在旧进程/云写未确认时切回旧路径。无未完成事务后可回到此前单次启动策略；关闭 autoStart 或退出仍必须取消队列，不能清除用户配置或自动打开登录项。
- 本轮文档可以撤销，不改变当前运行行为；独立日志修复不依赖此计划实施。
