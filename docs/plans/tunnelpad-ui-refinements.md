# 计划：TunnelPad 界面优化

- 状态：待实施（阶段 3；阶段 1 处于实施中收尾，见"阶段 1 记录"）
- 当前阶段：阶段 3（新增隧道）
- 最后更新：2026-08-29
- 前置：tunnelpad-v1 已完成（主窗口左右布局、设置弹窗、SSH 详细日志开关均已交付，commit `31345a4`、`b6c9796`）

## 背景

tunnelpad-v1 收档后，用户 2026-08-29 实机使用提出 8 项界面反馈：2 项为事实询问（已回答，不产生改动）、4 项为界面减法/行为修正、2 项为新功能（删除隧道、新增隧道）。本计划把这 8 项收敛为分阶段治理任务。

## 目标

按用户确认的取舍，完成主窗口界面减法、日志浏览体验修正，并补齐单条隧道的新增与删除能力。

## 非目标

- 不修改 config.json schema（新增/删除只增减 `tunnels[]` 数组条目）。
- 不改变隧道启停语义与"退出 app = 停止全部隧道"红线。
- 不做多选批量操作、不做隧道分组/排序/搜索。
- 不改动探针语义与执行器语义。

## 需求探索

### 已确认事实（2026-08-29 查证）

- 左下角两个按钮语义不同：`arrow.clockwise`=刷新状态（重查运行状态+重跑探针+重扫旧版 agent，只读）；`arrow.triangle.2.circlepath`=重新加载 config.json（外部手改配置后的手动同步入口，app 不自动感知外部修改）。两者均保留，悬停已有 `.help` 提示（用户询问第 5 项，已答复，无改动）。
- 「探针 401 ✓」= admin-tunnel 探针请求 `http://127.0.0.1:8081/admin` 返回 401，而 401 在该隧道 `expectedStatuses: [200, 401]` 内，表示隧道通、服务正常应答（用户询问第 8 项，已答复，无改动）。
- 现状基线：主窗口侧栏为 NavigationSplitView（带折叠控件）；footer 有 刷新/重新加载/全部启动/全部停止 四个控件；日志区 2s 定时器全量重绘文本并强制滚到底部；底部消息栏显示 `lastMessage`（已保存/已启动等信息文案）与 `lastError`（红色错误）；`TunnelManager` 现无新增/删除隧道的 API（commit `b6c9796`，`swift test` 55 用例全过）。
- 删除隧道不可逆：需停止实例（launchd bootout / app 停止）、清理生成的 plist 与 pidfile、删除日志文件、从 config.json 移除条目。

### 已确认决策（2026-08-29 grilling，用户确认）

| 决策点 | 候选 | 结论 |
|---|---|---|
| 删除防误触与范围 | A 确认弹窗+日志保留 / B 确认弹窗+日志一并清理 / C 不确认直接删 | **B：确认弹窗（显示隧道名），删除=停实例→清 plist/pidfile→删日志→从 config 移除** |
| 新增入口与初始状态 | A 预填 SSH 模板不自动启动 / B 空白表单不自动启动 / C 预填模板保存即启动 | **B：侧栏「+」打开空白新建表单（复用设置表单结构），id 按名称自动生成（冲突加序号），保存只落盘不自动启动** |
| 日志滚动交互（2026-08-29 实施中用户改定） | A 视口底部自动检测跟随（首轮实现，实机发现 macOS ScrollView+VStack 非懒加载、可见性探针失效） / B ModelPad 式：LazyVStack 按行渲染 + 显式「自动滚动」开关（参照 ModelPad `App/Sources/Views/LogView.swift`） | **B：与 ModelPad 同款交互，关开关即自由回看历史** |

## 不变量

- 退出 TunnelPad = 停止全部隧道（launchd bootout + app 执行器终止），不随本计划改变。
- config.json schema 字段与 version 不变；不读取私钥内容；ECS 地址不进仓库。
- 删除隧道必须先成功停止实例，再清理产物、移除配置；任何关键步骤失败不得留下"配置已删但实例仍运行"或反向的中间态。
- launchd plist 仍生成在 app 自己的 Application Support，不进 `~/Library/LaunchAgents`。

## 影响模块或文件

- `Sources/tunnelpad/MainPanelView.swift`：侧栏/footer/详情区/消息栏（阶段 1、3）。
- `Sources/tunnelpad/LogView.swift`：静默刷新与跟随逻辑（阶段 1）。
- `Sources/tunnelpad/TunnelSettingsSheet.swift` 或抽出共用编辑表单组件：新建表单复用（阶段 3）。
- `Sources/TunnelPadCore/TunnelManager.swift`：`removeTunnel`/`addTunnel` 进程内 API（阶段 2、3；不涉磁盘格式变化）。
- `Tests/TunnelPadCoreTests/`：对应新增用例。
- `docs/PLAN_MAP.md` 与本计划文件。

## 公共契约变化

无磁盘契约变化（config.json schema、launchd 标签约定均不变）。仅新增 `TunnelManager` 进程内 API 与 UI 行为变化。

## 风险和回滚

- 阶段 1 低风险：纯展示层行为迁移，revert 即回滚。
- 阶段 2 主要风险：删除为不可逆操作。缓解=确认弹窗（显示隧道名）+ 先停实例再删产物与配置 + 关键步骤失败即中断保留配置；删除后无自动恢复，重靠"新增"或重新接管流程重建。
- 阶段 3 主要风险：id 生成冲突或非法字符。缓解=沿用 `[a-z0-9-]+` 约束、冲突加序号、保存前唯一性校验。
