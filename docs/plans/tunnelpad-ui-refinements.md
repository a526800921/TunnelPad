## 背景

tunnelpad-v1 收档后，用户 2026-08-29 实机使用提出 8 项界面反馈：2 项为事实询问（已回答，不产生改动）、4 项为界面减法/行为修正、2 项为新功能（删除隧道、新增隧道）。本计划把这 8 项收敛为分阶段治理任务。

## 目标

按用户确认的取舍，完成主窗口界面减法、日志浏览体验修正，补齐单条隧道的新增与删除能力，并让菜单栏中的每条隧道都可直接启动或停止。

## 非目标

- 不修改 config.json schema（新增/删除只增减 `tunnels[]` 数组条目）。
- 不改变隧道启停语义与"退出 app = 停止全部隧道"红线。
- 不做多选批量操作、不做隧道分组/排序/搜索。
- 不改动探针语义与执行器语义。
- 不新增批量启动/停止入口；不把菜单栏单项点击扩展为配置编辑或删除入口。

## 需求探索

### 已确认事实（2026-08-29 查证）

- 左下角原有两个刷新入口语义不同：`arrow.clockwise`=刷新状态（重查运行状态+重跑探针+重扫旧版 agent，只读）；`arrow.triangle.2.circlepath`=重新加载 config.json（外部手改配置后的手动同步入口，app 不自动感知外部修改）。由于主窗口可见时已每 5 秒自动刷新运行状态与探针，现移除前者，仅保留重新加载 config.json。
- 「探针 401 ✓」= admin-tunnel 探针请求 `http://127.0.0.1:8081/admin` 返回 401，而 401 在该隧道 `expectedStatuses: [200, 401]` 内，表示隧道通、服务正常应答（用户询问第 8 项，已答复，无改动）。
- 现状基线：主窗口侧栏为 NavigationSplitView（带折叠控件）；footer 有 刷新/重新加载/全部启动/全部停止 四个控件；日志区 2s 定时器全量重绘文本并强制滚到底部；底部消息栏显示 `lastMessage`（已保存/已启动等信息文案）与 `lastError`（红色错误）；`TunnelManager` 现无新增/删除隧道的 API（commit `b6c9796`，`swift test` 55 用例全过）。
- 删除隧道不可逆：需停止实例（launchd bootout / app 停止）、清理生成的 plist 与 pidfile、删除日志文件、从 config.json 移除条目。

## 不变量

- 退出 TunnelPad = 停止全部隧道（launchd bootout + app 执行器终止），不随本计划改变。
- config.json schema 字段与 version 不变；不读取私钥内容；ECS 地址不进仓库。
- 删除隧道必须先成功停止实例，再清理产物、移除配置；任何关键步骤失败不得留下"配置已删但实例仍运行"或反向的中间态。
- launchd plist 仍生成在 app 自己的 Application Support，不进 `~/Library/LaunchAgents`。

## 风险和回滚

- 阶段 1 低风险：纯展示层行为迁移，revert 即回滚。
- 阶段 2 主要风险：删除为不可逆操作。缓解=确认弹窗（显示隧道名）+ 先停实例再删产物与配置 + 关键步骤失败即中断保留配置；删除后无自动恢复，重靠"新增"或重新接管流程重建。
- 阶段 3 主要风险：id 生成冲突或非法字符。缓解=沿用 `[a-z0-9-]+` 约束、冲突加序号、保存前唯一性校验。
- 阶段 4 主要风险：菜单状态与详情状态短暂不同步。缓解=打开菜单时先刷新，单项动作继续委托 `TunnelManager`，busy 时禁用；实机验证失败时仅回滚菜单入口改动。
